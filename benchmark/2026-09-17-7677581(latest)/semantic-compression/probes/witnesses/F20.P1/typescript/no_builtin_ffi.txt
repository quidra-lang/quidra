F20.P1 / TypeScript -- NONE evidence, captured on the frozen toolchain
host: Apple M2, macOS 26.4.1 arm64;  tsc 7.0.2, node 24.2.0
frozen semantic_compression recipe: tsc --strict --target es2022 --module nodenext FILE.ts ; node FILE.js

1. The TypeScript language itself has no foreign-function interface. The bundled
   lib.es2022.full.d.ts declares no mechanism for naming an external C symbol, and the
   TypeScript compiler emits JavaScript, never an object file.

2. The bundled runtime (node 24.2.0) exposes no FFI module. Command and output:
   $ node -e "console.log(require('module').builtinModules.join(' '))"
   _http_agent _http_client _http_common _http_incoming _http_outgoing _http_server
   _stream_duplex _stream_passthrough _stream_readable _stream_transform _stream_wrap
   _stream_writable _tls_common _tls_wrap assert assert/strict async_hooks buffer
   child_process cluster console constants crypto dgram diagnostics_channel dns
   dns/promises domain events fs fs/promises http http2 https inspector
   inspector/promises module net os path path/posix path/win32 perf_hooks process
   punycode querystring readline readline/promises repl stream stream/consumers

   trace_events tty url util util/types v8 vm wasi worker_threads zlib node:sea
   node:sqlite node:test node:test/reporters
   -- there is no ffi, no ctypes and no dlfcn module in that list.

   $ node -e "try{require('node:ffi')}catch(e){console.log('node:ffi ->',e.code,e.message.split('\n')[0])}"
   node:ffi -> ERR_UNKNOWN_BUILTIN_MODULE No such built-in module: node:ffi

3. process.dlopen exists but loads only a self-registering Node C++ addon, not an
   arbitrary platform C library, so it cannot reach `int abs(int)` in libSystem:
   $ node -e "process.dlopen({exports:{}}, '/usr/lib/libSystem.B.dylib')"
   Module did not self-register: '/usr/lib/libSystem.B.dylib'.
   Producing such an addon requires a C/C++ compiler and a separate build step outside
   the frozen recipe -> rubric criterion N-2.

4. node:wasi loads WebAssembly modules. Reaching the platform C `abs` through it would
   require compiling C to WebAssembly with a toolchain outside the frozen environment,
   and it would not be the platform C library the frozen recipe links -> N-2.

Conclusion: N-1 (no documented standard way to deliver any numbered sub-requirement with
the language's own built-in mechanism) with N-2 applying to every alternative examined.
