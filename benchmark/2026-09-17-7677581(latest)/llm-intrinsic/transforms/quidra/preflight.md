### Frozen rule C-4 (current stdout spelling)

C-4 of `methodology/00_cross_language_constraints.md` names TypeScript 7 and Zig 0.16 as
the two toolchains whose current stdout API differs from a widely-reproduced older idiom.
**This language is not one of them**: `print(value)` writes one line to standard output in
both 0.2.0 and 0.3.1, there is no superseded spelling a model could reproduce from an
older corpus, and no `Io`-instance or handle object is required (V17 is `NOT_LEXICALIZED`
here). The pack nonetheless states the current spelling explicitly, with its line-terminator
behaviour, in sections 8 and 10, and adds the one sentence C-4 asks for:

> `print` is the current spelling of the line-writing facility of this language version;
> there is no older alternative spelling to prefer.

That sentence is the same slot every language fills; it grants no extra explanation.

## Check (c) — the validator both accepts a correct input and rejects a corrupted one

`validate.py` runs eight checks: R0 forward match, R1 byte-identical round trip, R4
non-triviality, R5 domain containment, the section 4.2a conformance gate, then build, exit
status, and byte-exact stdout of the inverse image. It prints `ACCEPT` / `REJECT` and exits
non-zero on any failure.

**Accepts (three positives).**

```
$ python3 validate.py fixture_real.qui fixture_anon.qui fixture_expected.txt
R0_FORWARD PASS  R1_ROUNDTRIP PASS  R4_NONTRIVIAL PASS  R5_DOMAIN PASS
GATE PASS  BUILD PASS  RUN_EXIT PASS  RUN_STDOUT PASS      VERDICT: ACCEPT

$ python3 validate.py oracle_real.qui build/oracle_anon.qui expected_output.txt
... all eight PASS                                          VERDICT: ACCEPT

$ python3 forward.py build/stress_real.qui build/stress_anon.qui
$ python3 inverse.py build/stress_anon.qui build/stress_rt.qui
$ cmp build/stress_real.qui build/stress_rt.qui              (no output: byte-identical)
```

The stress fixture exists to prove the domain boundary rather than assume it. It contains
a comment naming six real keywords, a text literal whose content is the sentence
`"if for return int string else while"`, an interpolation with doubled braces, two
identifiers that contain keywords as substrings (`returns_here`, `for_each`), and a member
call `counter.string()` whose member name equals a reserved word. Forward leaves every one
of them untouched and the round trip is byte-identical.

**Rejects (five negatives).** Each mutation is different in kind, and each is caught by a
different subset of checks — a validator that could only detect one kind of damage would be
measuring almost nothing.

| Negative | Mutation | Checks that fired |
|---|---|---|
| `N1_real_keyword` | one pseudo-word replaced by the real keyword it stands for | `R0_FORWARD`, `GATE` |
| `N2_swapped_map` | two pseudo-words exchanged (integer type / text type) | `R0_FORWARD`, `R1_ROUNDTRIP`, `R5_DOMAIN`, `BUILD` |
| `N3_typo` | one pseudo-word misspelled by one letter | `R0_FORWARD`, `R1_ROUNDTRIP`, `R5_DOMAIN`, `BUILD` |
| `N4_ignores_transformation` | correct **real** source that ignores the transformation entirely | `R0_FORWARD`, `R4_NONTRIVIAL`, `GATE` |

### On section 10.4's warning about vacuous survival tests

10.4 warns that "did any transformed token survive?" is vacuous when the mapping is a
permutation of the language's own vocabulary. For I1 the mapping is **not** a permutation:
its codomain is 25 invented CVCVCV pseudo-words that occur nowhere in the language, in the
task material, or in the three rejection lists (filters 5 and 7 of `genmap.py` enforce
exactly this). A survival test is therefore not vacuous here — but it is also not what this
validator relies on. `R1` is a byte-identity test, `R5` compares the full token streams
position by position, and `BUILD`/`RUN_STDOUT` execute the inverse image and compare its
stdout to the oracle. N5 is the case that proves the difference: no transformed token is
damaged by it at all, so a survival test accepts it, while this validator rejects it on
three separate checks.

## Recorded residuals and stated limitations

1. **Standard vocabulary keeps its real spelling in I1** (`print`, `write`, `range`,
   `len`, and the `.string()` member). This is the I1 design (section 7.1), and it leaves
   the surface partly recognizable to a reader who already knows the language. Published as
   an anonymity residual, not corrected.
2. **`anonymized_token_count` = 25**, mechanically derived: every reserved word of this
   language that the task's construct set can reach. Six of the 25 (`pevoku`, `muzomu`,
   `dibego`, `silute`, `kesudu`, `mutitu`) are documented in the pack's table for
   completeness of the reserved surface, and the task needs none of them. Not quota-matched
   against the other nine languages, per section 7.1.
3. **Member-position asymmetry, deliberate.** `forward.py` never rewrites a word that
   directly follows `.` (it is a member name, never a grammar word token); `inverse.py`
   *does* map a pseudo-word in that position, so a submission that spells a member with a
   pseudo-word still maps back to buildable source instead of failing. This cannot break
   R1, because forward never emits a pseudo-word after `.` and no pseudo-word occurs in the
   task material (filter 7). Both positives and the stress fixture exercise the path.
4. **Whitespace insertions: zero.** Section 5.5's emission rule can never require an
   insertion here, because a complete WORD token can never have a word character as its
   neighbour; `qlex.substitute` asserts this on every run, so indentation — which is
   significant in this language — is preserved byte-for-byte and R1 needs no
   canonicalization step.
5. **Toolchain version.** Validated on 0.2.0 (the version in `environment.json`) and
   re-validated unchanged on 0.3.1. No behavioural difference was observed in any check.
6. **Comments.** Section 6.2 step 2 drops comments from fixtures during the forward pass.
   These transformers do **not** drop them; they pass comments through untouched in both
   directions. The fixture carries no comment, so the two policies coincide on every
   artifact here, and the stronger byte-identity invariant is what is tested.
